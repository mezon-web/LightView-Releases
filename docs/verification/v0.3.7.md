# v0.3.7 修正と検証

2026-10-22。更新・索引・復元と大量検索の不具合を修正しました。

| 対象 | 変更内容 |
|---|---|
| R01 自動更新 | 連続追記の通知をまとめ、書込みが続く間も更新を進めます。索引・検索・コピーが古い文書を使っている間は必要な読み取り資源を保持します。 |
| R02 内容照合 | 前の全領域を照合し、中央変更を追記と誤認しません。大きな文書は読み取った版を一時保持します。 |
| R03 読書位置 | 索引完成を待って保存位置へ戻り、F5で索引を作り直す間も目標を保持します。自分で移動した場合は待機中の復元を取り消します。 |
| R04 PDF文字位置 | 文字情報が多いページを一時ファイルへ退避し、再生成の繰り返しを防ぎ、選択・コピー・強調を維持します。 |
| R05 Markdown復元 | 同文段落・同名見出し・連続画像を区別し、遅延復元が次の操作を戻さないようにしました。 |
| R06 CSV更新 | 全レコードの構造を検査してから切り替え、不正な候補では直前の表・検索・フィルタ・選択を保持します。 |
| R07 大量検索 | 結果を最大512件ずつ配信し、ヒットデータの常駐量を約4MiBに抑えます。一覧更新をまとめ、退避した後半の結果も移動できます。索引途中の件数は未確定と表示します。 |

## 検証

Windows 11 x64の隔離デスクトップで、配布EXEと同じ発行済みDLLを使った **749項目**、10種類の文書の各3回起動、独立した7つの文書ウィンドウ、ZIP展開後のハッシュ、設定保持と通常終了を確認しました。100万2,001件のTXT/LOG/CSV検索、単一ページ10万ヒットのPDF、既定の文字位置cache予算を超える60万glyphのPDFも含みます。

GitHubからダウンロードしたZIPも、ローカルの検証済みZIPとの一致、内部ハッシュ、10種類の起動と設定保存を再確認しました。

## 性能・一時領域

実装段階の同一マシン・同一入力による各3回の中央値です。OSのファイルcacheは消去していません。

| 指標 | v0.3.6基準版 | 修正版 |
|---|---:|---:|
| PDF検索強調ありスクロール p95 | 16.81ms | 16.81ms |
| 約234MiB LOG 初回表示 | 32.90ms | 243.30ms |
| 約237MiB CSV 初回表示 | 54.66ms | 1,166.10ms |
| 24MiB LOG 追記読込 | 4.76ms | 28.14ms |
| LOG 索引後private memory | 209.59MiB | 209.98MiB |
| CSV 索引後private memory | 243.36MiB | 238.12MiB |

中央変更の検出のため、純粋追記でも前の全領域を読み取って照合します。24MiBの追記処理では一時allocationも約80KiBから約24MiBへ増えます。CSV/TSVは全体の構造検査後に表示するため、初回表示が遅くなります。大きな文書のsnapshotには元ファイル相当の一時ディスク領域が必要で、更新時は複数版が重なる場合があります。

PDF文字位置cacheの既定16MiBを維持しますが、最初の抽出時の配列は一時的に予算を超え得ます。検索の約4MiBにはチャンク索引や画面の管理情報を含みません。行索引、大量コピー、表の並べ替えのメモリ制約は残ります。一時ファイルはUserDataへ保存せず、元文書も変更しません。
